# Peranta セットアップ手順

Peranta は自前の ntfy サーバを介して通知・SMS を端末間で転送する。
構成要素は次の 3 種類で、この順に準備する。

1. **ntfy サーバ**: 全端末が接続する中継サーバ
2. **設定元の端末**（通常は Desktop）: 接続設定と共有鍵を作り、QR で他端末へ配布する
3. **参加端末**（Android スマホ / タブレット / 別の Desktop）: QR を読み取って参加する

## 1. ntfy サーバの準備

認証必須（匿名アクセス禁止）の ntfy サーバを用意し、Peranta 用のユーザー・ACL・
トークンを作成する。

```sh
# ユーザー作成（パスワードは安全な場所に控える）
ntfy user add peranta

# ACL: Peranta が使うトピックへの読み書きを許可する
ntfy access peranta "peranta-*" rw
# UnifiedPush 用。ntfy アプリが払い出す upXXXX トピックの購読/配送に必要
ntfy access peranta "up*" rw

# アクセストークン発行（Peranta の接続設定に使う）
ntfy token add peranta
```

開発時は `server/docker-compose.yml` でローカルサーバを起動できる（コメント参照）。

## 2. 設定元の端末（初期設定ウィザード）

初回起動すると初期設定ウィザードが開く。

1. **接続設定**: サーバホスト名・アクセストークン（・ポート）を入力する
2. **端末名**: この端末の表示名を入力する
3. **共有鍵の作成**: 「鍵を作る」で全端末共有の暗号鍵を作成する
4. **端末の追加**: 「QR を表示する」で参加端末向けの QR を表示する

QR にはサーバ接続情報と共有鍵が含まれる。表示は時間制限つきで、文字列としての
コピーもできる（取り扱い注意）。

## 3. 参加端末の追加

各端末で Peranta を初めて起動すると初期設定ウィザードが開く。設定元の QR を読み取る
（または文字列を貼り付ける）→ 端末名を入力して参加する。残りの権限・受信の準備は
ウィザードがそのまま案内し、あとからでも設定画面（ドロワーの「設定」）冒頭の
「セットアップ状況」から各画面（動作チェック・受信のセットアップ・接続設定と暗号キーの
取り込み）を開いて進められる。

### Android 送信端末（通知・SMS を転送する側）

ウィザード、または設定画面の「セットアップ状況」→[動作チェックを開く]の指示に従って
次を許可する。

- 通知へのアクセス（NotificationListener）
- バッテリー最適化の除外
- SMS の受信（SMS 直接受信を使う場合）

### Android 受信端末（UnifiedPush で通知を受け取る側）

受信には UnifiedPush ディストリビュータとして **ntfy アプリ**が必要。
ntfy アプリは Peranta とは独立した設定を持つため、次の手動設定が必要になる。
これらの作業台は Peranta の**受信のセットアップ**画面（設定画面の「セットアップ状況」→
受信経路の行→[受信のセットアップを開く]、またはウィザードの受信手順ページ）で、手順 1〜5 が
状態に依らず常時表示される。

1. ntfy アプリをインストールし、一度開いて通知の許可を済ませる
2. ntfy アプリの設定で **デフォルトのサーバーを自分の ntfy サーバに変更する**
   （例: `https://ntfy.example.com`）。初期値の `ntfy.sh` のままだと、Peranta の
   登録は成功したように見えて配信だけが届かない
3. サーバが認証必須の場合、認証情報を設定する。方法は次のどちらか一方:
   - **カスタムヘッダー（推奨・トークンだけで済む）**: ntfy の 設定 →「カスタムヘッダー」で、
     サービスURL にサーバの URL、ヘッダ名 `Authorization`、ヘッダ値 `Bearer <アクセストークン>` を追加する
   - ユーザー名/パスワード: 「ユーザー管理」でサーバ URL とユーザー（上で作成した
     peranta 等）を登録する。**URL は購読先と完全一致**させること（末尾スラッシュや
     http/https の違いでも紐付かない）
   - 両方は併用できない（同じサーバにユーザー登録があるとカスタムヘッダーの
     Authorization は設定できず、逆も同様）
4. Peranta の受信のセットアップ画面で「UnifiedPush の登録」を実行する
5. ntfy アプリのバッテリー最適化も除外する（受信のセットアップ画面が案内する）

なお手順 2〜3 で貼り付ける値は、受信のセットアップ画面に常設のコピーチップから取れる
（デフォルトのサーバーに貼るサーバーURL／カスタムヘッダーのサービスURL・ヘッダ名・ヘッダ値の
4 チップ＋[ntfy を開く]）。

デフォルトのサーバーを自分のサーバに変えると、他の UnifiedPush 対応アプリの通知も
自分のサーバ経由になる。それらを併用する場合は、サーバを公開インターネットから
到達可能にした上で ACL に匿名の書き込み許可（`ntfy access '*' 'up*' write-only`）を
追加する必要がある。

### Desktop 受信端末

QR 取り込み後、そのまま WebSocket で受信を開始する。ログオン時の自動起動は
設定画面の「セットアップ状況」→[動作チェックを開く]から登録できる。

## トラブルシューティング

- **送信は成功しているのに受信端末に届かない**: ntfy アプリのデフォルトのサーバーが
  自分のサーバになっているか確認する。Peranta はエンドポイントのトピックを
  「自分の設定サーバ」へ発行するため、ディストリビュータが別サーバを向いていると
  静かに失敗する
- **ntfy アプリのログに "WebSocket upgrade failed with HTTP 200"**: 認証失敗。
  ntfy アプリにユーザーが登録されていない（匿名購読）か、サーバ URL の不一致で
  ユーザーが紐付いていない。ユーザーを削除して作り直すと直ることがある
- **UnifiedPush の登録が反映されない**: ntfy アプリを一度開いてから Peranta の
  受信のセットアップ画面に戻ると、画面復帰のたびに状態を取り直して反映される
