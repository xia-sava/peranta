# Peranta

Android と Windows Desktop の間で通知・SMS・メッセージ・ファイルを転送する Kotlin Multiplatform
アプリ。中継は自前の ntfy サーバで、本文は端末間で E2E 暗号化する（サーバは暗号文しか扱わない）。

## 仕様

**`docs/spec.md` が仕様の単一情報源。** 実装と食い違いが出たら仕様を正とする。
コードのコメントは `（§3.4）` の形で節番号を参照している。

**仕様を変えたとき、機能を実装したときは、完了後に必ず `docs/spec.md` を修正する。**
コードだけ変えて仕様を古いまま放置しない。仕様の更新はその作業の一部であって、後回しにしない。

## モジュール

- `shared/` — ロジックの本体。`commonMain` に大半を置き、プラットフォーム固有だけ expect/actual
  で分ける（`androidMain` / `jvmMain`）。UI も Compose Multiplatform で共有する
- `androidApp/` — Android のエントリポイント（送信・受信を兼ねる）
- `desktopApp/` — Windows のエントリポイント
- `server/` — ntfy と Caddy の Docker Compose 一式
- `tools/` — アイコン生成などの補助スクリプト

## 検証

コミット前に必ず通す:

```
./gradlew check :shared:compileAndroidMain :androidApp:compileDebugKotlin :desktopApp:compileKotlin
```

- **`check` は androidMain のコンパイルを含まない。** 対象を明示して補わないと、androidMain が
  壊れたまま緑になる。
- **パイプは gradle の失敗を隠す。** `| tail` や `| grep` を通すとパイプ最後のコマンドの終了
  ステータスを見てしまうので、`set -o pipefail` を付けたうえで `BUILD SUCCESSFUL` を目視する。
- カバレッジは Kover。ロジック層は行カバレッジ 80% 以上を `koverVerify` で強制している（§16）。

## 版を上げる

`vMAJOR.MINOR.PATCH` のタグを push したときだけ配布物が出る。master への push では出ない。
手順と注意点は release skill を参照。

## コミット

- 件名は命令形で簡潔に。1 コミット 1 論理変更にまとめる
- 生成ツールのフッタ（`Co-Authored-By` 等）は付けない
- コメントに作業の経緯を書かない。結果としての仕様だけを書く
  （「○○せず△△する」ではなく「△△する」）
- 「今は〜」「後で〜」のような暫定的・時間的な記述を残さない。後続変更が確実な箇所だけ、
  具体的な条件を明記した TODO として書く
- その場かぎりの用語（会話中の造語、開発中のマイルストーン識別子など）を持ち込まない
